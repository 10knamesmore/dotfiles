# Prose Standard

写到足以保存读者依赖的约定，再删除重复和装饰。简短不以丢失条件、义务、例外或失败后果为代价；代码和类型没有表达的重要事实需要补齐。

## 编辑判断

- 保留谁做什么、何时及在什么条件下发生、必须或允许的程度、例外、所有权、失败行为和后果。易误用的规则保留最小具体原因。
- 写明实际行为、字段、单位、时机和结果。`contract`、`boundary`、`canonical` 等术语不能单独代替业务含义，也不是需要机械删除的禁词。
- 使用处保留读者当场需要的局部约定；长篇解释与历史只由一个文档持有，其他位置引用它。
- 普通文档与注释描述当前行为，引用须能从当前仓库或公共资料解析。活动 Spec 可以记录未来计划；ADR、postmortem、changelog 和完成态 evidence 可以保留可验证的历史、取舍和来源。

## 范围与依据

使用用户指定范围；已有 diff 是自然边界时只检查该 diff。审查只报告，获得修改授权后才编辑。保留第三方、fixture、snapshot、录制输出和冻结历史的原始内容；生成物从源头修改。

prompt、diagnostic 和 CLI/UI wording 可能影响行为，先确认消费者和真实含义。按当前句子涉及的问题读取源码、schema 或文档，不为局部措辞修改预读整个调用链。无法证实的内容不补写成事实。

## 按需读取

- 修改代码注释或文档注释：读 [comments.md](references/comments.md)，再按语言读取其中对应的规范。代码改动引入新语义或不变量时，检查是否需要同步注释；自明代码不制造注释。
- 文档覆盖范围不清楚：读 [document-types.md](references/document-types.md)。
- 需要校准删减是否丢失条件、modality 或证据：读 [examples.md](references/examples.md)。
- 专项排查或发现 session、PR、review 视角、过期快照、不可解析引用：使用 [trim-cot-leakage](../trim-cot-leakage/SKILL.md)，不把每次编辑扩成泄漏审计。

完成后核对含义、引用和实际行为，运行适合该文本的最窄已有检查。结果满足要求后停止，不为文风反复扩大审计。

有多种同样准确的表达时直接选清晰的一种。只有它们在已接受原则间存在真实取舍，且会影响行为或范围时才提出选择；用户要求逐项校准时再展示可行版本。
